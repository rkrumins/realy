# Contracts (locked before any service code)

Everything that crosses a process boundary is defined once under `contracts/` and generated into
Java (Gradle protobuf plugin) and Python (`scripts/gen-proto-python.sh`). CI regenerates and fails
on drift.

| Contract | File | Notes |
|---|---|---|
| Payment event | `proto/realy/payments/v1/transaction.proto` | production-shaped: **no** benchmark fields; amounts in minor units + normalised USD; `event_id = gen_id << 48 \| seq` |
| Ground-truth label | `proto/realy/payments/v1/label.proto` | separate topic, delayed (chargeback simulation) — never in the event (no leakage) |
| Feature vector | `proto/realy/features/v1/features.proto` | values in schema order + missing bitmap + per-entity freshness |
| Decision record | `proto/realy/scoring/v1/decision.proto` | the audit system of record: event, features as served, model, rules fired, policy, path, trace |
| Sync API | `proto/realy/scoring/v1/scoring_service.proto` | unary `Score` + bidi `ScoreStream`; unframed JSON accepted on the same port |
| Bench trace | `proto/realy/bench/v1/trace.proto` | in-band timing: intended/sent + per-stage spans with clock domains |
| Control / telemetry | `proto/realy/bench/v1/control.proto` | latency distributions, model capacity, scoring config, rate/phase/ingress commands, 1 s metrics snapshots (proto3 JSON) |
| Model protocol | `proto/kserve/v2/grpc_predict_v2.proto` | vendored KServe/Triton v2 (Apache-2.0), only Java options added |
| Feature DSL | `features/feature_schema.yaml` | drives Flink aggregators, online-store layout, model tensor order, ClickHouse columns, Python reference |
| Rules | `../rules/*.yaml` | versioned CEL; identical evaluation in Java (`dev.cel`) and Python (`cel`) |
| Topics | `kafka/topics.yaml` | partitions, keys, value types, timestamp types, retention, latency client settings |
| Online store | `storage/redis.md` | `fs:{entity}:{id}` / `pf:{entity}:{id}` binary blobs |
| ClickHouse | `storage/clickhouse/*.sql` | generated (`python -m realy.codegen`) Kafka engine → MV → ReplacingMergeTree + views |

## Kafka envelope

* key: `customer_id` (decimal ASCII) — all of a customer's activity is ordered in one partition;
  producers use murmur2 partitioning in both Java and librdkafka (`partitioner=murmur2_random`).
* headers: `x-bench-trace` (BenchTrace), `x-run-id`, `x-mirrored` (sync-path mirror),
  `x-backfill` (warm-start history: features only, never scored).
* record timestamp: intended wall time (event time is simulated and may be days ahead).

## Feature DSL semantics (identical in Java and Python)

* Event time drives windows; windows are bucketed: `k = floor(t / granularity)`, a window of `W`
  covers buckets `(k − W/g, k]`.
* `count/sum/max/avg/distinct` include the current event ("update, then read");
  `novel/time_since_last/geo_speed_kmh` compare with previous matching events, then update.
* Events without the entity get the default and the missing bit.
* Per-key order = Kafka partition order ⇒ customer and card features are fully deterministic;
  device/ip/merchant/terminal/payee features depend on cross-partition arrival order (as in production).

## Evolution rules

* Protobuf: add fields only; never renumber or change types; `buf breaking` against `main`.
* Feature schema: bump `schema_version` for any change to order/semantics; the online-store blob and
  Flink state carry the version (state resets on mismatch), decision records carry it, ClickHouse
  keeps `features_raw` so old versions stay replayable.
* Rules: every decision records `rule_set_version` (from the rule set's `version:`) and every rule
  that fired.

## Kafka headers on `payments.events.raw`

| Header | Set by | Meaning |
|---|---|---|
| `x-bench-trace` | emitter | `BenchTrace`: intended / sent time, clock domain, payload CRC; services append spans |
| `x-run-id` | emitter | the run the event belongs to (`<run>:backfill` / `<run>:prime` for unmeasured history) |
| `x-backfill` | emitter | history that only feeds Flink state; the gateway does not score it |
| `x-mirrored` | gateway (sync rail) | an event already decided synchronously, mirrored so Flink folds it into state |

## What ClickHouse keeps per decision

`realy.decisions` (generated by `python -m realy.codegen`; re-applying the DDL with `make migrate`
upgrades an existing install in place):
- the event fields;
- the outcome, score, path and reason codes;
- the exact served vector (`features_raw` and 54 `f_*` columns);
- **rule hits** (`rule_ids`, `rule_actions`);
- **per-entity freshness** (`fresh_entity`, `fresh_age_us`, `fresh_found`);
- per-stage latency columns;
- the broker's **append time** (`appended_at`, LogAppendTime) and `lat_audit_append_us`
  (decided → durably appended, 1 ms resolution).

The audit-ack span itself cannot be stored in the record it acknowledges; the sync client sees it
in the response trace.

Views:

| View | Contents |
|---|---|
| `v_training_dataset` | served features plus labels, with `label_time`, `label_delay_s` and `label_source` |
| `v_rule_performance` | per rule: fires, fraud fires, precision |
| `v_audit_gaps` | events without a decision |
| `v_latency_by_second` | per second, including the audit-append p99 |

## Config fields with live effect

- `ScoringConfig.review_threshold` / `decline_threshold`: values > 0 override the rule set's
  thresholds.
- `hedge_after_ms` (> 0): duplicates a model call that has not answered by then; the first response
  wins.
- `ModelServerConfig.weights_path`: hot-swaps the mock model server's weights.
- `rule_set_version` is reserved: the version comes from `rule_set_yaml`.
